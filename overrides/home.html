The problem

Agents guess.
Your standards don't.

Standards live in wikis and review comments, so an agent writing code at 2am never reads them. canon puts each one behind a tool the agent calls mid-task, and the answer always carries the reasoning.

Core concepts

Records, rules, profiles.
Nothing else to learn.

A record says what you decided and why. A rule maps a linter's output to a record. A profile says which records apply to which kind of repo.

Record

Markdown + YAML frontmatter

The decision, its context and its exceptions. The summary becomes the "why" in findings.

id: go-errors-wrap
status: accepted
strength: must
rules: [golangci-errors]

Rule

canon/rules/rules.yaml

Ties a checker's codes to a record. A finding without a rule is never reported.

- id: golangci-errors
  record: go-errors-wrap
  checker: golangci-lint
  codes: [wrapcheck, errorlint]

Profile

canon/profiles/*.yaml

Detects the kind of repo and selects the scopes of records in force.

name: go-cli
detect:
  all: [go.mod, cmd/]
scopes: [go, containers, ci, oss, yaml]

Quick start

Standards in your agent
in three commands.

You need Go 1.27 or newer to install from source. Linters are optional: canon reports which are missing and skips them.

{% include ".icons/material/book-open-page-variant-outline.svg" %} Full getting-started guide

  1. Install

    $ {{ install }}

  2. Give Claude Code the tools

    Registers the MCP server over stdio.

    $ claude mcp add canon -- canon serve

  3. Run your first check

    From the root of any repository.

    $ canon check
